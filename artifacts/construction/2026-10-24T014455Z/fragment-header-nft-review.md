# Native noninitial-fragment filtering and nft correspondence

The selected shared and baseline snapshots now have exact native nft hook checks in addition to raw iptables-save checks. The importer binds each namespace command to its captured container PID and complete device inventory. It checks the observed table, base-chain, priority, policy and ordered-rule inventories. Only an omitted, empty ACCEPT chain may be reconstructed from the iptables rendering. Missing nonempty or default-deny chains and additional earlier hooks are rejected.

The Lean partial-header model does not read TCP/UDP ports or ICMP type/code from a noninitial IPv4 fragment. Its accepted packets are included in the complete-header model for every assignment to those missing fields when all explicit rules allow. The shared and baseline INPUT, FORWARD and OUTPUT chains contain 325 and 219 explicit ACCEPT rules respectively. Default policies remain unchanged. The ordered-list proof depends on the absence of an earlier transport-specific DENY rule. A regression demonstrates that counterexample.

The nft JSON exports expose some xt matches by name rather than their full parameters. The importer checks those names and their rule positions against raw iptables-save. The parameter correspondence therefore retains the iptables-nft rendering contract. It does not claim independent decoding of opaque netlink match data. The capture represents the selected state, not arbitrary future rule changes.

The official Linux v6.8 source is retained in references/fragment-authentication-v6.8 with URL, final URL, retrieval time and hashes. The packet-info code retains the IPv4 protocol and fragment offset. The nft payload evaluator rejects transport-header reads on noninitial fragments. The xt transport/multiport matchers similarly reject those reads. Address-only routing and the imported address-only XFRM selectors are independent of the unavailable transport values. These facts connect the missing-field abstraction to the selected supported match language.

The source review does not assume that every gateway reassembles before forwarding. Conntrack initialization enables IPv4 defragmentation where that facility is loaded. The native gateways do not all have a conntrack rule. Local IPv4 delivery reassembles before protocol delivery. ESP input rejects failed authentication before delivering the decoded payload. The retained upstream source is an implementation-family reference for the captured Ubuntu 6.8.0-138 backend, not a byte-for-byte verification of its kernel binary.

The accepted-fragment filtering bridge is proved and applied. Authenticated encrypted reassembly and its connection to per-byte origin histories remain separate actionable work. Ordinary IP fragment keys do not prove shared security provenance, and source annotations are not wire fields.

Validation retained in experiments: twelve native nft mutation/positive tests, the FragmentHeaders Lean regression, and complete native reimports. The shared and baseline regenerated Lean files are byte-identical to their existing modules. validation/native-nft-regeneration-comparison.json records both hashes.
