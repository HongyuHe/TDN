# Nested IPv4 packet-size checks

The retained two-IPsec-layer experiment records fourteen data-path interfaces across eight devices. Red interfaces use MTU 1100, the Inner Gray outputs use 1200, and the Outer Black outputs use 1400. The other selected interfaces use 1500. Both the configured observation and the later stable observation report the same limits. Every imported interface and XFRM record is checked against its raw command, namespace, exit status and output.

A packet changes length at each encryption layer. Under the selected minimal-padding IPv4 ESP encoding, a 1100-byte Red datagram becomes 1156 bytes on Gray and 1212 bytes on Black. Each encoding adds a 20-byte outer IPv4 header, 8-byte ESP header, 8-byte explicit IV and 16-byte integrity value, together with a 2-byte trailer and alignment padding. The recorded states use tunnel mode and GCM with a 128-bit integrity value. The importer rejects recorded UDP encapsulation, TFC padding and unsupported state shapes. Minimal padding and the absence of additional outer IPv4 options remain implementation assumptions.

`NestedPacketSizing.lengthAt` selects the packet length appropriate to each interface. `length_at_monotone` reuses monotonicity of the component encodings. `all_sizes_fit_each_interface` then proves that checking the maximum size at each interface covers every smaller size. The concrete application checks all fourteen interface budgets with `by decide` and applies the unchanged theorem. Mathlib's monotone ordering and the existing `PacketLength.aligned_wire_length_monotone` provide the required library results. No new transition-system infrastructure is introduced.

The new result contributes to RG033's packet-size obligations for the selected geometry. The current encompassing `PacketSizing` definition compares a single final encoded length with several different interface limits. The new result makes the intermediate lengths explicit and avoids requiring a Black-length packet to fit an earlier Gray interface. The subsequent stage-specific correction gives the encompassing definition separate external, Outer and Black length functions. Its general budget and monotone proofs check those functions independently. Whole-group application still requires complete applicable interface and path evidence.

The proof assumes that the selected packet follows the represented two-layer path, that the source limit is enforced, and that the recorded settings remain fixed. The importer does not independently prove all route choices or all possible forwarding executions. It does not establish that every arbitrary incoming packet is below the limit. The raw observations and hashes establish traceability; collector truth and implementation behavior remain assumptions. Observations at two times do not establish stability between those times.

Nine importer tests cover the actual case, missing devices, raw-output mismatch, namespace mismatch, insufficient Gray or Black limits, changed limits, changed integrity size and TFC padding. The Lean regression checks that a 1200-byte Black limit fails even though the Inner packet fits that size. Dedicated Lean compilation and regression results are preserved under the run's experiments directory. The supplemental namespace backend is retained explicitly; the result is not attributed to a native FRR/OVS deployment. MACsec and other applicable network cases remain open.
