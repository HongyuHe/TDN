# COORD-047: distinguish the certificate subject from the generation process

The CP requires the encryption component to generate its key pair and CSR. The coordinator inspected section 6.1 on PDF page 29, printed page 22. The IPsec paragraph assigns generation to the Inner and Outer VPN Gateways. The certificate-based MACsec paragraph assigns generation to the corresponding encryption components. The rendered source is retained as `references/macsec-fallback/cp-page-29.png`.

The previous `ProvisioningEvent.component` field identified the intended component. The field did not record where the generation or request command executed. A worker-generated key could therefore have been labeled with its intended component and satisfied the earlier predecessor condition. No concrete complete RG-048 application had been established through that condition, but the general specification omitted the execution boundary.

The updated event adds an executor with three possibilities: a modeled component, a worker, or unobserved. The default is unobserved. The request predecessor now requires both the generation event and the CSR event to execute at their named component. A strengthened general theorem proves that every admitted installation has an earlier component-generated key with the matching public-key identity. The original ancestry theorem remains available as a consequence. A separate lemma rejects a worker-origin generation event even when its intended component and key reference match the request.

The retained forward and reverse EAP experiments generate their supplicant keys on the worker. Their raw command records explicitly have `device_id: null`, and the pinned collector invokes `openssl genpkey` and `openssl req` without entering either peer namespace. Later configuration files point to those generated files. The importer checks generation, request, and signing order, successful exit statuses, matching file paths, and configuration references. The two observations are retained as worker execution; they are not relabeled as component execution.

The records provide command dependencies without exposing key or CSR contents. No per-stage public-key fingerprint is invented. Successful OpenSSL execution and unchanged files connect those paths operationally. The current contribution checks the available ordering facts and establishes that the worker-origin records cannot discharge the component-generation premise. It does not establish the full provisioning requirement.

A repair remains technically straightforward: generate the private key and CSR within the chosen device boundary, export the CSR, sign it at the intended CA, and return the certificate and chain. The current run cannot execute that repair because remote actions remain restricted after the earlier automated screening interruption. The restriction leaves the run incomplete. It does not make the requirement mathematically unprovable or justify ending independent work.

The device boundary must be stated for every backend. Network namespaces share a worker kernel and may share a filesystem, but the present experiment records device-specific execution separately from worker execution. A future model that assigns an additional key-generation service to the encryption component would need explicit architecture and isolation evidence. Matching a private file path alone cannot establish that assignment.

Seven importer mutations pass. They reject changed execution location, wrong key or CSR paths, failed generation, reversed timing, and duplicate generation. Lean regression cases distinguish component-local generation from worker generation and also reject a worker-created CSR. General and concrete modules compile. One failed Lean attempt projected through a conditional before reducing the request kind; the corrected proof and the failure are preserved.

The changes are in `TDN/Targets/Provisioning.lean`, `TDN/Evidence/FreshProvisioningLocations.lean`, `scripts/construction/import_provisioning_locations.py`, `tests/test_provisioning_locations.py`, and `tests/ProvisioningExecutor.lean`. The facts and limitations are in `fresh-provisioning-locations.json`. Independent Construction review and register updates are pending. Optional administration does not become a premise of the management-free packet proofs.
