# RG-027: EAP key sources and fallback credentials

The new contribution checks four MACsec peers across the two retained EAP arrangements. Each public configuration is parsed completely. Unknown fields, duplicates, extra network blocks, include directives, and control-interface configuration are rejected. The importer confirms that actual peer logs report EAP-created MKA participants. A changed log reporting pre-shared creation is rejected.

The general model records the origin of each participant's CAK. An authenticated exchange adds an EAP-origin participant. Pre-shared creation requires both configured fields. Other steps remove participants or preserve their origins. CSLib's `mtrInv_of_trInv` extends that one-step argument to every finite sequence. The evidence module checks the imported configuration flags with `by decide`, then applies the same general theorem to each peer.

The source review found two creation entry points in each relevant wrapper. The EAP path derives the CAK and CKN from authenticated session material. The pre-shared path returns before creation unless `mka_psk_set` contains both flags. The reviewed upstream configuration parser initializes a fresh record with zeroed storage and sets those flags through `mka_cak` and `mka_ckn`. The complete upstream archive caller inventory contains the expected wrapper calls and the function definition. Exact retained wrapper/core hashes and binary observations reuse the existing MACsec binding importer.

The source-to-binary connection remains a stated implementation assumption. The retained artifacts do not contain a reproducible build or every final compiled source file. The evidence includes reviewed upstream configuration-parser source, exact modified wrappers/core, binary hashes, and the collector that created and launched the initial configurations. Configuration changes after startup and arbitrary memory changes fall outside the fixed-configuration execution model.

The interpretation of MD-15 is recorded separately in `interpretations/INT-MD15-20261024.md`. The proof allows normal EAP renewal and multiple EAP participants. No key-generation approval is inferred from a successful authentication or a source-code hash. RG-027 remains partial.

Nine importer tests pass. They check both real role arrangements and reject added key fields, extra network blocks, includes, management-driven configuration entry points, duplicate fields, changed authentication modes, contradictory creation modes, and missing creation logs. The first Lean attempt failed because constructor pattern names included parameters already fixed by induction. The corrected general and concrete modules compile. A separate Lean regression permits pre-shared creation when both fields are present and checks that the resulting state fails the EAP-only invariant. Failed attempts and exact source versions remain preserved.
