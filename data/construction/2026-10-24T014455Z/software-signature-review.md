# RG-073 software-signature evidence review

The CP Table 2 row names ML-DSA category 5 with parameter ML-DSA-87. The retained software-signing-v3 experiment signs a manifest for one Twinet executable. The source document identifies the permitted algorithm. NIST's official algorithm registry identifies the binary public-key algorithm value. The captured NIST source, URL, retrieval times and hashes are preserved under references/software-signatures.

The new importer reads the saved experiment without executing its loader, payload or altered controls. It checks every bundle hash, the reviewed collector and loader source hashes, exact command paths, read-only payload mounts, command order and successful key generation/signing records. It decodes the saved public-key structure, requires the parameter-free ML-DSA-87 identifier, and compares every public-key byte with the recorded OpenSSL text dump. It checks the retained successful launch and both rejection records. It does not independently run the cryptographic signature verifier.

The general theorem takes a complete component list and signature-use records. Each component must have a record, and every record must use an approved algorithm. The proof finds a corresponding record for each component, establishes a nonempty signature list and transfers approval from each record to the component's signature list. The same proof supports different component inventories. Algorithm approval is checked by ordinary Lean computation for the selected ML-DSA parameters.

The concrete application names one deployment utility. The utility is not a substitute for CSfC Solution Components. RG-073 remains incomplete because the retained case does not inventory or sign every device executable, library, firmware image or boot path. The manifest's publisher is a laboratory identity. Publisher authorization, trusted key installation, correct OpenSSL execution, stable files and collection remain explicit assumptions. Executing an opened file descriptor alone does not establish that another writer cannot change its contents.

Ten importer tests reject changed key identifiers, inconsistent public-key bytes, altered key and payload paths, changed rejection outcomes, unreviewed loader source, collection errors, reordered commands and malformed key encoding. The Lean regression covers multiple components, multiple artifacts for one component, a missing component, wrong ML-DSA parameters and an unapproved alternative. The general and concrete modules compile. Initial missing Decidable-instance failures are retained with their repair. No new remote operation, loader execution or loader-injection probe occurred.

The reusable proof uses existing Mathlib list membership and filtering facts. It introduces no new general execution framework. Complete device signing remains a separate evidence/implementation task. The current isolated run cannot claim whole RG-073 compliance from the utility example.
