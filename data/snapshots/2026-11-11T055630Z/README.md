# EAP-TLS completion and MACsec key installation

These two collections record EAP-TLS authentication through a central RADIUS server, MKA key distribution, and MACsec key installation. They were collected on November 11, 2026 on `clnode176.clemson.cloudlab.us` in isolated network namespaces. The forward collection uses P0 as authenticator and key server, with P1 as supplicant. The reverse collection swaps those roles. Each arrangement delivered all three ping packets in both directions.

The captures share the test CA and authentication-server certificate. Each arrangement has its own session and derived key references. A key reference is a SHA-256 digest of observed key material. Secret keys and the private RADIUS shared secret are excluded. The public configuration files, certificates, daemon messages, commands, and collection manifests remain available in each collection.

The additional messages connect the server's authentication completion to both peers' key derivation. Instrumentation records the exact Access-Accept bytes sent by the server and the same response accepted by the authenticator. It also records the forwarded EAP-Success bytes at transmission and receipt. Packet observations corroborate EAP-Success on both interfaces. The parser connects events through process order or matching messages. It does not infer cross-process causality from timestamps alone.

The MCP parser is `eap-complete-causal-v1`. Its `authentication_complete_history` export retains event references, causal links, EAP input records, MKA messages, and key installations. The two configured collection IDs are `eap-tls-forward-v32-complete-causal` and `eap-tls-reverse-v32-complete-causal`.

The [collector](../../../scripts/construction/evidence/collect_eap_correlation.py) runs both arrangements and removes private credentials afterward. The [completion instrumentation](../../../scripts/construction/evidence/patch_hostap_eap_completion.py) extends a hostap 2.12 source tree already instrumented by the correlation, public-handshake, and MKA-message scripts in the same directory. Use an isolated source copy. The extension refuses previously patched files and records before/after hashes. The capture used OpenSSL 3.5.5 in the existing `tdn-hostap-pq:20261024-v3` lab image. Every collection records the actual hostap binary identities and collector source hashes.

The observations support the selected model applications under the stated collection and implementation assumptions. Public messages and key hashes do not independently verify TLS signatures, RADIUS integrity, or MACsec cryptography. The forwarding applications use explicitly identified model packet and key representations. Any additional routed attachment in a model profile is recorded separately from the captured two-peer topology.
