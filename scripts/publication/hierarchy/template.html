Why are there several definitions and proofs per RG?

A top-level specification states the conditions required by one RG. A group can contain several clauses, and its analysis can use several definitions, theorems, and lemmas. The search and category filters select the visible second-layer boxes. The locator moves to a box without expanding it. An entry can establish only part of the RG.

A general proof takes a network and explicit assumptions as inputs. Its argument applies to any network represented by the model that meets those assumptions. A model application supplies a particular configuration, checks the required conditions, and applies a general proof. Some applications use imported observations; others use constructed examples. Their stated assumptions determine what they establish about a running network.

The categories organize proofs by source file: general proofs come from the reusable semantics and requirement modules; model applications and checks come from the evidence modules. The source statement gives the exact scope of each proof. Both categories contain theorems and lemmas. The colors follow the source keyword: theorems express main results, and lemmas supply intermediate results.
